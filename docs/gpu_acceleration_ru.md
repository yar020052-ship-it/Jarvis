# GPU-ускорение JARVIS

JARVIS использует видеокарту для задач, которые действительно поддерживают CUDA или аппаратный графический рендеринг. Захват микрофона и экрана, интерфейсные события, файловые операции и сетевые запросы остаются на CPU: видеокарта не ускоряет эти операции.

## GTX 1080 Ti

GTX 1080 Ti построена на архитектуре Pascal (Compute Capability 6.1). В Windows-установщике JARVIS проверяет сборку PyTorch и при обнаружении NVIDIA-карты автоматически устанавливает `torch==2.14.1+cu126`, если текущая сборка не содержит поддержку `sm_61`. Это CUDA-сборка PyTorch для Pascal; обычная сборка `+cpu` CUDA не использует. CUDA 12.6 выбрана специально: начиная с PyTorch 2.15 готовые CUDA-сборки больше не включают Pascal.

Проверка выполняется во время Windows setup. Она нужна один раз; затем PyTorch не переустанавливается, если его сборка уже содержит нужную архитектуру. Размер CUDA-пакета для скачивания — около 2,6 ГБ. После установки перезапустите JARVIS, чтобы активный процесс загрузил CUDA-библиотеки.

## Что получает GPU-ускорение

- **Голографическое лицо:** слой `QOpenGLWidget` рисует лицо через OpenGL. JARVIS пишет имя фактического OpenGL-рендерера в журнал. Расчёт позы и подготовка геометрии остаются CPU-задачами.
- **Локальная речь Kokoro:** если выбран движок Kokoro, PyTorch отправляет синтез на CUDA. При ошибке CUDA движок пересоздаётся на CPU.
- **Локальная оценка подачи голоса FunASR:** модель выбирает CUDA и при проблеме загрузки повторяет инициализацию на CPU.
- **Локальный Whisper:** CTranslate2 самостоятельно проверяет CUDA-доступность; при проблеме с CUDA или cuDNN распознавание повторяет запуск на CPU. Работа GPU зависит от CUDA/cuDNN DLL, доступных CTranslate2.
- **Системный монитор:** уже показывает загрузку NVIDIA GPU через NVML.

## Что не переносится на локальную GPU

- Gemini Live, облачный TTS и другие внешние ИИ работают на серверах провайдеров.
- Штатные `opencv-python` и ONNX Runtime в текущем окружении не предоставляют локальному коду CUDA Execution Provider. Захват изображения и часть обработки остаются на CPU.
- Остальные Qt-виджеты и бизнес-логика JARVIS не являются нейросетевыми вычислениями. Лицо вынесено на OpenGL; полный переход интерфейса на GPU потребовал бы замены его QWidget-отрисовки и не ускорил бы сами сетевые/системные операции.

CPU fallback сохраняется для каждого локального ML-движка, если CUDA или подходящая библиотека недоступна.
