# Диагностика компьютера, Wi-Fi и камеры

После перезапуска JARVIS обнаруживает эти действия автоматически.

## Компьютер

- `system_diagnostics overview` — нагрузка CPU/RAM, количество процессов, свободное место на системном диске.
- `system_diagnostics processes` — процессы с наибольшим потреблением CPU и RAM.
- `system_diagnostics storage` — свободное место по дискам.
- `system_diagnostics startup` — записи из стандартных разделов автозапуска Windows. Команды автозапуска не выполняются и не изменяются.

## Wi-Fi и интернет

`wifi_diagnostics full` читает состояние адаптера, имя сети, сигнал, канал, драйвер, IP, шлюз и DNS, а также проверяет DNS и доступность внешнего TCP-порта. `wifi` показывает состояние адаптера; `connectivity` проверяет только связь. Диагностика ничего не переключает и не сбрасывает.

## Камера

В Windows команда `camera_control list` выводит названия DirectShow-устройств и их индексы, не открывая видеопоток. `camera_control select` принимает уникальную часть имени или индекс. После выбора `screen_process` и локальный предпросмотр используют эту камеру. Установка Windows-зависимости `pygrabber` нужна для получения Friendly Name; без неё перечисление названий не выполняется. Кадры захватываются только по явному запросу; `open_camera` оставляет локальное превью до команды закрыть камеру.

## Составные задачи

При многошаговой просьбе JARVIS должен продолжать цепочку инструментов по их фактическим результатам и проверить итог. Например, диагностика камеры включает список устройств, проверку выбранной камеры кадром только по запросу и проверку приватности/доступа Windows. Если шаг упирается в системное разрешение, код сопряжения или другую локальную настройку, JARVIS сообщает точное действие, которое нужно сделать на устройстве.
