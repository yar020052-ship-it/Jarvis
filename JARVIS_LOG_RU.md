## 1. Два ключа Gemini с автоматическим переключением

В проекте реализована поддержка **двух ключей Gemini**:

- Ключ 1 — основной (`gemini_api_key`)
- Ключ 2 — резервный/фолбэк (`gemini_api_key_2`)

### Логика переключения при исчерпании квоты

Когда модель возвращает ошибку квоты (429 / `RESOURCE_EXHAUSTED` / `quota` / `rate limit`):

1. Модель ставится на cooldown (временный отдых).
2. Пробуется та же модель на втором ключе.
3. Если и второй ключ исчерпал квоту — переходим к следующей модели в лесенке.
4. Если все модели на обоих ключах исчерпали квоту — возвращается `None` (ответ не получен).

**Переключение между ключами происходит автоматически**, дополнительных действий не требуется.

### Где прописать второй ключ

Файл: `config/api_keys.json`

```json
{
  "gemini_api_key": "ВАШ_ПЕРВЫЙ_КЛЮЧ",
  "gemini_api_key_2": "ВАШ_ВТОРОЙ_КЛЮЧ"
}
```

Или через системные секреты (`core.secrets.get_secret("gemini_api_key_2")`).

## 2. Приоритет моделей (лесенка)

Модели перебираются от самых подходящих к менее подходящим.  
**Для каждой модели сначала пробуется ключ 1, потом ключ 2**, и только затем следующая модель.

### Итоговый порядок моделей

| Задача (tier) | Порядок моделей (первый = приоритетный) | Argon |
|---|---|---|
| **FAST** — быстрые решения, классификация | `3.5-lite → 3.5 → 3.6 → 3.8 → LIVE` | ❌ не используется |
| **SMART** — обычные рассуждения, документы | `3.8 → 3.6 → 3.5 → 3.5-lite → argon → LIVE` | в конце |
| **CODE** — написание и ревью кода | **`argon → 3.8 → 3.7 → 3.6 → 3.5 → LIVE`** | **в начале** |
| **REPAIR** — автопочинка JARVIS | **`argon → 3.8 → 3.7 → 3.6 → LIVE`** | **в начале** |
| **VISION** — разбор снимков и изображений | `3.8 → 3.6 → argon → LIVE` | в конце |
| **STRATEGY** — стратегическое планирование | `3.8 → 3.6 → argon → LIVE` | в конце |
| **SEARCH** — поиск с источниками | `3.8 → 3.6 → 3.5 → 3.5-lite → argon` | в конце |

### Почему так

- **Бесплатные модели вперёд** — для большинства задач сначала используются бесплатные Flash-модели, чтобы экономить квоту.
- **Argon только где нужен** — для кода и автопочинки Argon идёт первым, потому что там нужен самый сильный разум. Для остальных задач Argon в конце — как резерв на случай, если бесплатные модели исчерпали квоту.
- **Два ключа** — каждая модель пробуется на обоих ключах перед переходом к следующей модели.

## 3. Cooldown (отдых модели после ошибки)

Когда модель получает ошибку:

| Ошибка | Действие | Время отдыха |
|---|---|---|
| Квота исчерпана (429) | Модель отдыхает | `retryDelay` из ошибки, или до полуночи по Тихоокеанскому времени (если `PerDay`) |
| Модель недоступна (404/403) | Модель откладывается | 6 часов |
| Модель не отвечает (503/504/таймаут) | Модель отдыхает | 30 минут |
| Ollama недоступен | Ollama отдыхает | 5 минут (после 3 неудач) |

Во время cooldown модель пропускается, чтобы не hammer'ить API лишними запросами.

## 4. Что было изменено в коде

### Файл `core/gemini.py`

1. **Функция `api_key(refresh, key_num)`** — добавлен параметр `key_num` (1 или 2) для выбора основного или резервного ключа. Ключи кэшируются отдельно.

2. **Функция `call()`** — переписана логика перебора моделей и ключей:
   - Собираются все доступные ключи (явный, основной, резервный).
   - Формируется список попыток: каждая модель из лесенки × все ключи.
   - Порядок: модель 1 → ключ 1, модель 1 → ключ 2, модель 2 → ключ 1, модель 2 → ключ 2, и т.д.
   - При ошибке квоты модель ставится на cooldown и переход к следующей попытке.
   - При отсутствии ключей — вывод сообщения и возврат `None`.

3. **Лесенки моделей (`_LADDERS`)** — приоритет пересмотрен:
   - FAST: начинается с самых быстрых и дешёвых моделей.
   - SMART/CODE/REPAIR/VISION/STRATEGY/SEARCH: Argon перемещён в конец (кроме CODE и REPAIR, где он первый).
   - Добавлена поддержка интерливинга двух ключей.

## 5. Логирование на русском (консоль + файл)

Все сообщения модуля Gemini теперь выводятся **на русском языке** одновременно в:

- **Консоль** (stdout) — сразу при запуске JARVIS
- **Файл лога** — `jarvis_gemini.ru.log` в папке пользовательских логов (по умолчанию `%LOCALAPPDATA%\JARVIS\logs\jarvis_gemini.ru.log` или рядом с проектом при разработке)

Формат записи:
```
29.10.2026 00:00:05 [Gemini] задача=CODE выбрана модель=gemini-4-argon [primary]
29.10.2026 00:01:12 [Gemini] модель Live gemini-3.8-live превысила квоту — пропуск на 300 секунд.
29.10.2026 00:01:13 [Gemini] модель gemini-4-argon [fallback]: недоступен для этого ключа — откладываем в сторону
```

Уровни сообщений:
- `INFO` — успешный выбор модели и ключа
- `WARNING` — ошибка квоты, модель недоступна, не отвечает, ключ не настроен

## 6. Оптимизация переключения (быстрое отключение Fallback)

Если fallback-ключ (ключ 2) также получает ошибку квоты на какой-либо модели, система запоминает это (`both_keys_drained = True`) и для **всех остальных моделей** пробует только основной ключ. Второй ключ почти наверняка тоже пуст — не тратим время на лишние API-запросы с таймаутом.

**До оптимизации:** при квоте на обеих ключах делалось до 6 моделей × 2 ключа = 12 запросов перед сдачей.  
**После оптимизации:** 1 модель × 2 ключа + остальные × 1 ключ ≈ 7 запросов. Время ожидания сокращено примерно в два раза.

## 7. Отслеживание квоты Gemini (прямой доступ к состоянию)

JARVIS теперь ведёт локальный учёт запросов по каждому API-ключу и **проверяет квоту перед отправкой реального запроса**, чтобы не тратить время на холостые вызовы с таймаутом.

### Как это работает

1. **Файл состояния:** `config/quota_state.json` — хранит таймстампы запросов и моменты ошибок 429 для каждого ключа (ключ хранится в зашифрованном виде — только 16-символьный хеш SHA-256, открытый ключ не записывается).
2. **Перед каждым вызовом:** `can_proceed(key)` проверяет:
   - Был ли 429 на этом ключе менее 5 минут назад — если да, запрос не посылается.
   - Превышен ли лимит запросов в минуту (по умолчанию 15) — если да, пропуск.
   - Превышен ли лимит запросов в сутки (по умолчанию 1500) — если да, пропуск.
3. **После каждого вызова:** `record(key, success, is_quota_error)` фиксирует результат. При 429 ставится метка `last_429`, ключ блокируется на 5 минут.
4. **Лимиты настраиваются:** в `api_keys.json` под ключом `gemini_quota_limits` можно задать индивидуальные `rpm` и `rpd` для каждого ключа.

### Пример записи в логе

```
29.10.2026 19:59:46 [Gemini] gemini-4-argon [primary]: локальная оценка квоты исчерпана — пропуск без запроса
29.10.2026 19:59:47 [Gemini] задача=CODE выбрана модель=gemini-3.8-flash [primary]
```

### Настройка лимитов (`api_keys.json`)

```json
{
  "gemini_api_key": "ВАШ_КЛЮЧ_1",
  "gemini_api_key_2": "ВАШ_КЛЮЧ_2",
  "gemini_quota_limits": {
    "<хеш_ключа_1>": {"rpm": 15, "rpd": 1500},
    "<хеш_ключа_2>": {"rpm": 15, "rpd": 1500}
  }
}
```

Хеш ключа можно получить, запустив JARVIS один раз — он запишется в `config/quota_state.json`.

## 6. Рекомендации

1. Обязательно добавь второй ключ в `config/api_keys.json` (`gemini_api_key_2`), иначе переключение при квоте не сработает.
